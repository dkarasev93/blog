# 📰 Вечерний Валидатор

**№ 4.** *Лондон. Туман густ, как смола в трубке. Сыщик оставил надзор за конторой mytonctrl и спустился ниже — в само машинное отделение, где на C++ крутится валидатор сети TON.*

*Место происшествия: репозиторий [ton-blockchain/ton](https://github.com/ton-blockchain/ton), коммит [`bb935a83`](https://github.com/ton-blockchain/ton/commit/bb935a83e8da44a367dc211f264c8ffa13cb7ca1) (master от 03.08.2026), файл [`crypto/vm/db/DynamicBagOfCellsDbV2.cpp`](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/crypto/vm/db/DynamicBagOfCellsDbV2.cpp). Все цитаты дословные.*

## СЕНСАЦИЯ: МЕХАНИЗМ, ПРИЗНАЮЩИЙСЯ В СОБСТВЕННОЙ ГЛУПОСТИ

Первое, что наш сыщик увидел, откинув крышку люка, — табличку, вывешенную самими механиками. Строка 17:

```cpp
// Very stupid Vector/MpmcQueue
template <class T>
struct TsVector {
```

Так и написано: очень глупый вектор. Не «экспериментальный», не «временный» — глупый, причём с нарицательным «Very». Подобная честность в Лондоне редка: обычно на дверях пишут «Банк», а внутри — контора по переписыванию запятых (см. выпуск № 3). Здесь же проспект прямо в аннотации.

Но разбирательство не доверяет самооговорам и изучает механизм по чертежам. А чертежи, милостивый читатель, таковы, что газовый рожок в кабинете эксперта замигал. Вот как вектор отыскивает элемент по номеру — строки [35–46](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/crypto/vm/db/DynamicBagOfCellsDbV2.cpp#L35-L46):

```cpp
  T &at(size_t i) {
    td::uint64 j = i / first_block_size_;
    td::int32 hb = 63 - td::count_leading_zeroes64(j);  // hb = -1 if j=0, else hb>=0

    // If j=0, hb<0, so hb>>31 = -1 => mask=0
    // If j>0, hb>=0, so hb>>31=0  => mask=~0 (all ones)
    td::uint64 mask = ~(td::uint64)(hb >> 31);

    size_t block_i = hb + 1;
    uint64_t shift = hb & 63ULL;
    uint64_t start = ((1ULL << shift) * first_block_size_) & mask;
    size_t pos_in_block = i - start;
```

Вникните: вместо скучного массива указателей механики устроили каббалу из ведущих нулей, арифметического сдвига знакового числа и маски, добываемой из сдвига минус единицы. Справиться с этим за один вечер может лишь тот, кто её и сочинил, да и то — по свежей памяти. Комментарии рядом честно толкуют фокус, но читаются как записки фокусника самому себе: «если j равно нулю, сдвиг даст минус один, следовательно маска — ноль». Холмс, ознакомившись, попросил бы повторить медленно — и это сыщик с уже привычкой к странному.

Впрочем, ад — не в адресации. Ад — в ожидании. Строки 64–71, выемка из начала очереди:

```cpp
  T pop_front() {
    auto pos = begin_.fetch_add(1, std::memory_order_relaxed);
    while (pos >= end_.load(std::memory_order_acquire)) {
      // This may (or may not) use too much CPU
      td::this_thread::yield();
    }
    return std::move(at(pos));
  }
```

Переведём с механического: покуда товар не завезли, клерк крутится на месте и вежливо уступает стул соседу — `yield`, — но стул тут же занимает снова. А над вертушкой висит табличка, достойная рамы: «This may (or may not) use too much CPU» — «это может (а может и не может) истратить слишком много процессора». Разбирательство отмечает: наука покуда не установила, жрёт механизм процессор или не жрёт; механики честно признаются, что сами не ведают. Очередь, между прочим, бесконечно растущая и никогда не сжимающаяся: `size()` — это просто `end_`, вынутые элементы из счёта не вычитаются, блоки, коих 64, не отдаются назад. Глупый вектор, как и положено глупому, помнит всё и прощает ничего.

И наконец — исповедь в конце фолианта. Строки 1536–1544, сохранение разницы в хранилище:

```cpp
  void save_diff(CellStorer &storer) {
    td::PerfWarningTimer timer("celldb_v2: save_diff");
    td::PerfWarningTimer timer_store_to_db("celldb_v2: save_diff_store_to_db", 0.01);
    // Have no idea hot to parallelize this in case of rocksdb
    for (auto &diffs : diff_chunks_) {
      for (auto &diff : diffs) {
        storer.apply_diff(diff).ensure();
      }
    }
```

«Have no idea hot to parallelize this» — «понятия не имеем, кАк это распараллелить»: механики машинного отделения, жарко ругаясь («hot» вместо «how» — перо, видимо, дрожало), признаются прямо в протоколе, что самая тяжёлая часть службы останется однопоточной, ибо rocksdb. Таймер с порогом в сотую секунды над этим признанием тикает, как хронометр у смертного одра.

## ХРОНИКА МЕЛКИХ ПРОИСШЕСТВИЙ

*Отдел мусоросжигания.* В [`tdutils/td/utils/HazardPointers.h`, строки 109–110](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tdutils/td/utils/HazardPointers.h#L109-L110), обитает сборщик мусора, представленный канцелярией так:

```cpp
    // stupid gc
    std::vector<std::unique_ptr<T, Deleter>> to_delete_;
```

«Stupid gc» — глупый сборщик, — и рядом, по бокам, забиты подкладки `pad` до линии кэша: мусорщика утеплили, но умнее он от этого не стал. Разбирательство отмечает закономерность: в машинном отделении TON всякий механизм, в коем механики не вполне уверены, честно подписан «глупым». Честность — лучшая политика, особенно когда исправлять всё равно никто не собирается.

## ВЕРДИКТ РЕДАКЦИИ

Газета вынуждена признать, что держит машинное отделение в уважении: это не подвал mytonctrl, здесь знают слово «memory_order» и пишут его правильно. Но и здесь, под котлами валидатора, крутится вектор, окрещённый глупым собственными родителями, крутится вертушка с табличкой «может, жрёт процессор, а может, нет», и тикает таймер над исповедью «have no idea».
