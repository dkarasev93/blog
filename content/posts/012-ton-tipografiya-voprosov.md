# 📰 Вечерний Валидатор

**№ 12.** *Лондон. Туман нынче не серый, а чернильный: пахнет типографской краской и нерешёнными вопросами. Наш корреспондент вновь спускается в машинное отделение [ton-blockchain/ton](https://github.com/ton-blockchain/ton) — но минует котельную с «очень глупым вектором» (выпуск № 4) и кладовую ключей с «dummy secret» (выпуск № 11), а направляется в крыло, о котором мало кто слышал: в типографию. Именно здесь, в [`crypto/tl/tlbc-gen-cpp.cpp`](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp), стоит ротационный станок, который по TL-B-схемам печатает весь сериализационный код сети — каждую грамоту, каждую расписку, каждый блок. Сыщик поднял лист из-под пресса. Лист был усыпан знаками вопроса.*

*Место происшествия: репозиторий [ton-blockchain/ton](https://github.com/ton-blockchain/ton), коммит [`3d478cb`](https://github.com/ton-blockchain/ton/commit/3d478cbde854be03a18ab2a59f8fc3c565cf7d14) (master от 17.08.2026). Все цитаты дословные.*

## СЕНСАЦИЯ ПЕРВАЯ: ПРЕСС ПЕЧАТАЕТ «RETURN -1; // ???» — И ПОДПИСЫВАЕТСЯ

Сердце типографии — механизм, определяющий, каким тегом помечена каждая конструкция: по нему весь город читает чужие грамоты. Функция `generate_get_tag_subcase`, файл [`crypto/tl/tlbc-gen-cpp.cpp`](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp), строки [758–762](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp#L758-L762):

```cpp
void CppTypeCode::generate_get_tag_subcase(std::ostream& os, std::string nl, const BinTrie* trie, int depth) const {
  if (!trie || !trie->down_tag) {
    os << nl << "return -1; // ???";
    return;
  }
```

Осмыслите происшествие при газовом рожке. Это не комментарий в коде — это комментарий, **печатаемый в чужой код**. Станок, доходя до тупика в дереве тегов, не молчит: он набирает в кассе три знака вопроса и оттискивает их прямо в сгенерированный лист, рядом с `return -1`. И это не единственный станок с такой привычкой: соседняя функция `generate_get_tag_param` делает то же самое в строке [797](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp#L797) — `os << nl << "return -1; // ???";`. Два станка, один почерк, три знака вопроса на каждый тупик. Типография не скрывает, что печатает загадки. Типография гордится тиражом.

Но подлинный шедевр ждёт в конце той же `generate_get_tag_param`, строки [881–884](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp#L881-L884):

```cpp
  os << nl << "// ??? cannot distinguish constructors for this type using up to three parameters\n";
  throw src::Fatal{std::string{"cannot generate `"} + cpp_type_class_name + "::get_tag()` method for type `" +
                   type.get_name() + "`"};
```

Здесь сыщик постоял молча. Станок сперва честно отпечатывает в лист свою исповедь — «не могу различить конструкторы этого типа даже по трём параметрам», со знаками вопроса впереди, — а затем, не поднимая глаз, бьёт себя же фатальным молотом: `throw src::Fatal`. Признание в бессилии напечатано раньше, чем брошено исключение. Порядок важен: сначала надгробие, потом смерть. В нуаре это называется предусмотрительностью.

## СЕНСАЦИЯ ВТОРАЯ: «SKIP SOME IMPLICIT FIELDS ???» — КАПСЛОК ОТЧАЯНИЯ

Второй оттиск найден в двух цехах сразу. Цех упаковки, функция `generate_pack_method`, строка [2804](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp#L2804):

```cpp
        // skip SOME implicit fields ???
```

И цех объявлений, функция `declare_record_pack`, строка [2938](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp#L2938):

```cpp
      // skip SOME implicit fields ???
```

Поймите драматургию. Пропускаются не «все» неявные поля и не «некоторые» — а SOME, заглавными, с криком, и следом три знака вопроса. Это не комментарий, это записка, приколотая к станку в три часа ночи: «мы пропускаем НЕКОТОРЫЕ неявные поля???». Какие именно — типография не уточняет. Сыщик проверил окрестности: в обоих местах пропускаются все поля с `implicit`, так что SOME — чистой воды театр. Но театр остался в чистовике, закоммичен и с тех пор пугает ночных читателей капслоком, как фонарь пугает кошек.

А в функции `output_actions`, строка [1822](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/tl/tlbc-gen-cpp.cpp#L1822), станок доводит жанр до минимализма: если список действий оказался неполным (`incomplete`), в лист печатается просто `os << nl << "// ???";`. Без слов. Три знака вопроса как дипломатическая нота. Сыщик не решился спросить, что именно не доделано; у тумана свои правила приличия.

## СЕНСАЦИЯ ТРЕТЬЯ: ЗНАКИ ВОПРОСА ДОБРАЛИСЬ ДО САМОЙ МАШИНЫ

Сыщик, уже ничему не удивляясь, прошёлся по отделению с фонарём — и обнаружил, что зараза «???» вышла за пределы типографии. Вот сердце всей сети, виртуальная машина, файл [`crypto/vm/vm.cpp`](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/vm/vm.cpp), строка [212](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/vm/vm.cpp#L212):

```cpp
    cr.set_c0(std::move(ret));  // ??? if codepage of code in ord_cont is unknown, will end up with incorrect c0
```

Перевод для вечернего читателя: при передаче управления по продолжению машина ставит в регистр c0 — тот самый, откуда исполняется код, — значение, про которое честно пишет: если кодовая страница неизвестна, c0 окажется **неправильным**. И это не черновик: та же строка с тем же комментарием повторена слово в слово двадцатью строками ниже, в строке [232](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/vm/vm.cpp#L232). Сомнение скопировано методом «копировать—вставить» вместе с кодом, к которому оно относится. Дважды подписано, дважды запечатано тремя знаками вопроса. Машина, исполняющая каждый контракт города, хранит у себя в регистрах маленькую тёмную комнату с табличкой «???» — и, судя по всему, держит её запертой уже не первый год.

Но и это не дно. Вот палата стражи — валидатор, проверяющий заголовки блоков, файл [`validator/impl/validate-query.cpp`](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/validator/impl/validate-query.cpp), строки [551–553](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/validator/impl/validate-query.cpp#L551-L553):

```cpp
  if (after_split != after_split_) {
    // ??? impossible
    return fatal_error("after_split mismatch in block header");
  }
```

«Невозможно» — с тремя знаками вопроса. Стража уверена, что ветвь недостижима, но на всякий случай вооружила её фатальной ошибкой и припиской, в которой сомневается в собственной уверенности. А в том же протоколе, строка [7460](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/validator/impl/validate-query.cpp#L7460), перепись конфигурации завершается фразой: `// config:key_block?ConfigParams -> checked in compute_next_state() and ???` — «проверено в compute_next_state() и…». Что «и» — история умалчивает. Протокол обрывается на союзе, как депеша, оборванная туманом.

## ХРОНИКА МЕЛКИХ ПРОИСШЕСТВИЙ

*Отдел телеграфа.* В телеграфной конторе tonlib, файл [`tonlib/tonlib/TonlibClient.cpp`](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/tonlib/tonlib/TonlibClient.cpp), строка [6039](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/tonlib/tonlib/TonlibClient.cpp#L6039), при оформлении нулевого состояния сети в графу «шард» вписан ноль, а на полях — пометка клерка: `//TODO check wether shard indeed 0???`. Заметьте великолепие: сомнение выражено одновременно тремя способами — словом «check», опечаткой «wether» вместо «whether» и тремя знаками вопроса. Трижды спрошено, ноль раз проверено. Шард, впрочем, действительно ноль — у нулевого состояния мастерчейна иного не бывает, — так что пометка висит на полях как декорация: сомнение ради сомнения, с опечаткой в придачу.

*Отдел надгробий.* В разборщике FunC, файл [`crypto/parser/symtable.cpp`](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/parser/symtable.cpp), строка [118](https://github.com/ton-blockchain/ton/blob/3d478cbde854be03a18ab2a59f8fc3c565cf7d14/crypto/parser/symtable.cpp#L118), стоит эпитафия, написанная самим могильщиком: `delete cur_def;  // ??? keep the definition always?` — «удалить определение; ??? хранить определение всегда?». Сперва хоронит, потом спрашивает, не стоило ли оставить покойника в живых. Порядок действий, заметит читатель, ровно тот же, что у типографского станка: сначала необратимое, потом вопросительный знак.

## ВЕРДИКТ РЕДАКЦИИ

Скажем по справедливости: каждый из этих «???» — не катастрофа. Тупиковые ветки с `return -1` законны, «невозможная» ветвь валидатора, скорее всего, и впрямь недостижима, а тёмная комната в регистре c0 освещена годами боевой работы: если бы кодовая страница терялась, город бы заметил. Но газета ведёт хронику почерка, а не арифметики. И почерк гласит: в машинном отделении заведена привычка разговаривать с будущими читателями знаками вопроса. Станок печатает «???» в чужой код. Машина помечает «???» собственный регистр. Стража пишет «??? impossible» над фатальной ошибкой. Клерк спрашивает «wether???» над вписанным нулём. Могильщик спрашивает «always?» над свежей могилой. Всё это работает — и всё это подписано тремя знаками вопроса, как анонимные письма. Туман над Темзой, по обычаю, всё принял — но, кажется, впервые задумался: а не он ли сам понаставил эти знаки?
