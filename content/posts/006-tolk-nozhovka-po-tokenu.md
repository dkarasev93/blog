# 📰 Вечерний Валидатор

**№ 6.** *Лондон. Туман валит из труб литейного двора и стелется по мостовой, как расплавленный свинец. Сыщик минует машинное отделение, где в выпуске № 4 был изобличён «очень глупый вектор», и стучится в соседний цех — туда, где отливают шрифт нового наречия сети: язык Tolk, преемник почтенного FunC.*

*Место происшествия: репозиторий [ton-blockchain/ton](https://github.com/ton-blockchain/ton), коммит [`bb935a83`](https://github.com/ton-blockchain/ton/commit/bb935a83e8da44a367dc211f264c8ffa13cb7ca1) (master от 03.08.2026), цех [`tolk/`](https://github.com/ton-blockchain/ton/tree/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tolk). Все цитаты дословные.*

Прежде чем читатель возмутится, поясним ремесло. Словолитня — она же лексер — глотает исходный текст и отливает из него слитки-токены. По закону жанра словолитня жадна: видит два знака `>>` подряд — и отливает их одним слитком. Чертежи подтверждают, [`tolk/lexer.cpp`](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tolk/lexer.cpp#L562), строка 562:

```cpp
    register_token(">>", 2, tok_rshift);
```

И всё бы ничего, кабы не дженерики. Когда читатель языка пишет `Wrapper<Wrapper<int>>`, парсеру нужны две скобки по отдельности, а в руках у него — один сдвоенный слиток, отлитый намертво. Как выходит из затруднения почтенный цех? Сейчас увидите. Газовый рожок, будьте любезны, поближе.

## СЕНСАЦИЯ ПЕРВАЯ: ТОКЕН, РАСПИЛЕННЫЙ НАДВОЕ

Протокол разбирательства, [`tolk/ast-from-tokens.cpp`, строки 284–292](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tolk/ast-from-tokens.cpp#L284-L292):

```cpp
    } else if (lex.tok() != tok_cl) {
      // overcome the `>>` problem, like `Wrapper<Wrapper<int>>`:
      // treat token `>>` like two `>`; consume one here doing nothing (break) and leave the second `>` in a lexer
      if (tok_cl == tok_gt && lex.tok() == tok_rshift) {
        lex.hack_replace_rshift_with_one_triangle();
        out_range.end(lex.cur_range());
        break;
      }
```

Имя процедуры не выдумано нашим фельетонистом и не подобрано адвокатом. Оно подлинное: `hack_replace_rshift_with_one_triangle`. «Hack» — в собственном паспорте механизма, без экивоков. Сам обряд распила, [`tolk/lexer.cpp`, строки 636–641](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tolk/lexer.cpp#L636-L641):

```cpp
void Lexer::hack_replace_rshift_with_one_triangle() {
  // overcome the `>>` problem when parsing generics, leave only `>` here, see comments at usage
  tolk_assert(cur_token.type == tok_rshift);
  cur_token = Token(tok_gt, ">");
  cur_token_offset++;
}
```

Вникните, милостивый читатель, в анатомию приёма. Словолитня не возвращается в поток и не перечитывает текст — нет. Она вынимает из буфера уже отлитый слиток, заменяет его одиночной скобкой и сдвигает внутренний указатель на один знак — то есть **пилит токен посередине**: одна половина выдаётся парсеру как честная `>`, вторая остаётся лежать в лексере, как недорезанная монета под прилавком, до следующего визита. Стража при обряде — `tolk_assert`: пилить дозволено только `>>` и только в цеху дженериков, дабы ножовка не ушла гулять по городу.

Справка редакции для публики, далёкой от словолитного дела: ровно та же напасть донимала когда-то великое герцогство C++. Там её разрешили указом — стандарт 2011 года велел читать `>>` внутри шаблонов как две скобки, и вопрос закрыли декретом, без хирургии. Пятнадцать лет спустя на берегах Темзы предпочли ножовку и честное слово «hack» в реестре. Редакция не судит: у всякого герцогства свои законы, у всякой словолитни — своя пила.

## СЕНСАЦИЯ ВТОРАЯ: ЛИТЕРАЛ-ПРИЗРАК БЕЗ МЕТРИКИ

Второй эпизод скромнее, но душевнее. Цеху понадобилось, чтобы у встроенных функций был параметр по умолчанию `{}` — пустой свёрток. Написать его в исходнике стандартной библиотеки нельзя: значения по умолчанию вычисляются через синтаксическое дерево, а дерева у встроенных функций нет — они родились вне грамматики. Что делает цех? Куёт узел дерева вручную. [`tolk/builtins.cpp`, строки 2102–2106](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tolk/builtins.cpp#L2102-L2106):

```cpp
  // in stdlib, there is a default parameter `options = {}`; since default parameters are evaluated with AST,
  // emulate its presence in built-in functions; it looks ugly, but currently I don't have a better solution
  auto v_empty_PackOptions = createV<ast_object_literal>(SrcRange::undefined(), nullptr, createV<ast_object_body>(SrcRange::undefined(), {}));
  v_empty_PackOptions->assign_struct_ref(struct_ref_PackOptions);
  v_empty_PackOptions->assign_inferred_type(PackOptions);
```

Читайте метрику младенца: `SrcRange::undefined()` — «место рождения: нигде». Узел-призрак: в исходниках его нет, в файле ему не лежать, а в дереве он сидит как родной, с присвоенным типом и пришитым структурным паспортом. Приписка мастера над верстаком честна до мурашек: «it looks ugly, but currently I don't have a better solution» — «выглядит скверно, но лучшего решения у меня пока нет». Редакция ценит такие записи: лучше признание на полях, чем табличка «Банк» на дверях притона. Но заносим в протокол: призрак размножен по меньшей мере в дюжине экземпляров — `T.toCell`, `T.fromCell`, `Cell<T>.load` и далее по списку — и всякий раз с одной и той же подделанной метрикой.

## ХРОНИКА МЕЛКИХ ПРОИСШЕСТВИЙ

*Отдел временных мер.* В лавке при цехе, [`tonlib/tonlib/tonlib-cli.cpp`](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tonlib/tonlib/tonlib-cli.cpp#L113-L114), сыщик отметил табличку над глобальным указателем на планировщик — строки 113–114:

```cpp
// Temporary hack
td::actor::Scheduler* global_scheduler_{nullptr};
```

Временная мера, введённая на уровне всего процесса: планировщик хранится в глобальной переменной, чтобы любой желающий мог до него дотянуться. А на строке [2308](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tonlib/tonlib/tonlib-cli.cpp#L2308) — та же мера, вывешенная вторично, при инициализации: `// temporaty hack`. Читатель, вглядитесь в правописание: «temporaty». Временность успела состариться и обзавестись глобальным указателем, а вот орфография осталась временной в самом буквальном смысле — не дописанной.

*Отдел карманного театра.* Та же словолитня держит под рукой карманную труппу из восьми токенов: `tolk/lexer.h`, строка [153](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tolk/lexer.h#L153) — `Token tokens_circularbuf[8]{};`, а листает её по масочке, `tolk/lexer.cpp`, строка [622](https://github.com/ton-blockchain/ton/blob/bb935a83e8da44a367dc211f264c8ffa13cb7ca1/tolk/lexer.cpp#L622) — `cur_token = tokens_circularbuf[++cur_token_idx & 7];`. Ловко, компактно, викториански: взгляд в будущее словолитни ограничен ровно восемью слитками. Восьмой удар — и прошлое токена накрывает его же собственное будущее.

## ВЕРДИКТ РЕДАКЦИИ

Скажем по совести: цех Tolk — дело новое и по-человечески понятное. Грамматика свежая, комментарии честные, виновные подписаны собственными именами — «hack» здесь, «ugly» там. После контор, где парсер собирают из сообщений об ошибках (выпуск № 3), читать такое — почти отдых. Но протокол есть протокол: слиток `>>` распиливается ножовкой вместо декрета, литерал рождается без места рождения, а «временная» мера дожила до второй вывески и опечатки. Туман над литейным двором, как обычно, всё видел — и нынче сгустился ровно на один токен.
