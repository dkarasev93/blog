# ВЕЧЕРНИЙ ВАЛИДАТОР

*Газета газовых фонарей, пыльных мемпулов и бессонных нод*

## ДЕЛО О ПЕРЕВОДЕ, КОТОРЫЙ УШЕЛ БЕЗ СТУКА

Лондон тонул в тумане, когда сыщик «Вечернего Валидатора» получил папку из [TONresistor/teleton-agent](https://github.com/TONresistor/teleton-agent). На обложке обещали честный перевод: дождаться настоящей транзакции в сети и не выдавать оптимистичный успех. Газовый рожок одобрительно кашлянул.

Потом сыщик заглянул в [коммит e3c5924](https://github.com/TONresistor/teleton-agent/commit/e3c592435a5b46e07ae81453a20f127b6c64be27), в [src/ton/transfer.ts](https://github.com/TONresistor/teleton-agent/blob/e3c592435a5b46e07ae81453a20f127b6c64be27/src/ton/transfer.ts). И обнаружил мелочь, от которой у любого владельца кошелька должен зазвенеть колокольчик: параметр `bounce` существует, но по умолчанию получает значение `false`.

## УЛИКА ПЕРВАЯ: ТИШИНА ВМЕСТО ОТСКОКА

На [строках 10–15](https://github.com/TONresistor/teleton-agent/blob/e3c592435a5b46e07ae81453a20f127b6c64be27/src/ton/transfer.ts#L10-L15) контора описывает отправку так:

> ```ts
> export interface SendTonParams {
>   toAddress: string;
>   amount: number;
>   comment?: string;
>   bounce?: boolean;
> }
> ```

До сих пор все выглядит прилично: отправитель может выбрать режим. Но на [строке 27](https://github.com/TONresistor/teleton-agent/blob/e3c592435a5b46e07ae81453a20f127b6c64be27/src/ton/transfer.ts#L27) сыщик находит решение за кулисами:

> ```ts
> const { toAddress, amount, comment = "", bounce = false } = params;
> ```

`false` здесь не просто отсутствие галочки в анкете. При отключенном bounce неудачная доставка не обязана вернуться отправителю. Ошибка в адресе или перевод на еще не развернутый контракт может превратить монеты в письмо без обратного адреса. А функция называется буднично — `sendTon`, так что подозреваемый пользователь может и не заметить, что получил режим «отправить и не ждать ответа».

## УЛИКА ВТОРАЯ: ПЕЧАТЬ НА КОНВЕРТЕ

В [строках 52–55](https://github.com/TONresistor/teleton-agent/blob/e3c592435a5b46e07ae81453a20f127b6c64be27/src/ton/transfer.ts#L52-L55) это значение без дополнительного дознания уходит в сообщение:

> ```ts
> const sent = await sendWalletTx(client, contract, {
>   secretKey: keyPair.secretKey,
>   messages: [internal({ to: recipientAddress, value: toNano(amount), body: comment, bounce })],
> });
> ```

Документально все сходится: адрес проверен, ключ взят, транзакция подтверждается в сети. Но флажок безопасности передан как есть, а его значение по умолчанию уже выбрано в пользу тишины. У пользователя остается один шанс не отправить монеты в туман — явно передать `bounce: true`. Это особенно выразительно для функции, которая принимает обычные параметры, а не просит подтвердить опасный режим отдельной печатью.

## ВЕРДИКТ СЫЩИКА

В [комментарии к функции](https://github.com/TONresistor/teleton-agent/blob/e3c592435a5b46e07ae81453a20f127b6c64be27/src/ton/transfer.ts#L19-L23) обещано: вернуть подтвержденную транзакцию, а не оптимистичный успех. Обещание про факт транзакции исполнено. Но подтверждение того, что деньги вернулись после неудачной доставки, — уже другая история: `bounce` выключен заранее.

Приговор прост: в кошельке опасный режим не должен быть молчаливым значением по умолчанию. Иначе газовый рожок протрубит слишком поздно — уже после того, как письмо ушло без обратного пути.
